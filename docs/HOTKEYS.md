# Активация голосового ввода

## Коротко

По умолчанию:

| Действие | Кнопка |
|---|---|
| Открыть окно прослушивания | боковая мышь **«вперёд»** (mouse5) |
| Говори, пока держишь (push-to-talk) | боковая мышь **«назад»** (mouse4) |
| То же с клавиатуры | `Ctrl+Space` |

После активации у тебя **8 секунд** на фразу (`wake.listen_timeout_s`).
Ассистент ждёт конца речи + 600 мс тишины, потом отвечает.

## Настройка

Всё в `data\config.yaml`, раздел `wake`:

```yaml
wake:
  mode: hotkey          # hotkey — ждёт активации; none — слушает всегда
  mouse_button: mouse5  # открыть окно
  hotkey: ctrl+space    # то же с клавиатуры, работает одновременно
  push_to_talk: mouse4  # удержание
  listen_timeout_s: 8.0
```

Кнопка мыши и клавиша включаются **одновременно**. Это страховка: если софт
мыши съел боковую кнопку, ассистент остаётся управляем с клавиатуры.

### Что можно написать

| Значение | Что это |
|---|---|
| `mouse1` … `mouse5` | кнопки мыши (mouse4 — «назад», mouse5 — «вперёд») |
| `back`, `forward` | то же словами |
| `назад`, `вперёд` | по-русски |
| `middle`, `средняя` | колесико как кнопка |
| `ctrl+space`, `f9`, `alt+f4` | сочетания клавиш |
| `ctrl+mouse5` | кнопка мыши с зажатым ctrl |
| `none` | выключить |

Для `push_to_talk` разрешено сочетание из одних модификаторов (`ctrl+shift`) —
там нужно **удержание**, а не нажатие. Для обычной активации запрещено:
`ctrl+shift` нажимает кто угодно, ассистент просыпался бы на ровном месте.

Перезапуск после правки конфига:

```powershell
.\run_sinaps.bat run
```

## Если кнопка не работает

Проверь перехват отдельно — так сразу видно, доходит ли событие до нас:

```powershell
.\run_sinaps.bat hotkeys --seconds 10
```

Команда покажет, какие из настроенных кнопок система отдаёт, а какие нет:

```
Что ищем:
  • боковая «вперёд» (mouse5)        [mouse5      ] открыть окно
  • ctrl+space                       [ctrl+space  ] открыть окно
  • боковая «назад» (mouse4)         [mouse4      ] удержание

Нажимай что-нибудь 10 с. Ctrl+C — выход.

  поймано: mouse5       (окно на 8 с)

Итог:
  [OK]  боковая «вперёд» (mouse5)
  [--]  ctrl+space — не поймана
```

Подсказки в конце зависят от того, что именно не поймано.

### Если не поймано вообще ничего

Перехват не работает в этой сессии целиком:

- **Ассистент запущен от администратора, а браузер — нет** (или наоборот).
  Перехват видит только ввод внутри своей сессии. Запусти оба одинаково.
- Сессия без интерактивного рабочего стола — служба, удалёнка без GUI.
- Сработала блокировка всплывающих окон или антивирус.

### Если не поймана боковая кнопка мыши

Три причины по убыванию частоты:

1. **Кнопка в Windows настроена как «Навигация».**
   Параметры → Мышь → Дополнительные параметры → вкладка «Кнопки мыши».
   Кнопки 4 и 5 должны стоять в режиме **«Обычный»**, а не «Навигация».
   В режиме навигации система бронирует их под переходы назад/вперёд.
2. **Перехватил софт мыши** — Logitech G Hub / Options+, Razer Synapse,
   X-Mouse, Corsair iCUE. Сними назначение «назад/вперёд» в той программе.
3. **Кнопки нет физически.** У простой мыши боковых кнопок может не быть.

Что попробовать дальше — в конфиге одна строка:

```yaml
wake:
  mouse_button: mouse3   # средняя кнопка, есть у любой мыши
  push_to_talk: mouse4   # или наоборот поменять 4 и 5 местами
```

### Если не срабатывает сочетание клавиш

Занято другой программой: PowerToys, AutoHotkey, Antikbd, игровое ПО.
Или перехвачено системой: `Ctrl+Esc` открывает «Пуск». Попробуй `f9`
или `ctrl+shift+f9`.

## Режим «слушать всегда»

```yaml
wake:
  mode: none
```

Микрофон открыт постоянно, активация не нужна.

**Включай только с наушниками.** Через колонки ассистент услышит собственный
ответ и начнёт выполнять команды сам. Без наушников получится петля обратной
связи.

## Состояния

| Состояние | Что происходит |
|---|---|
| 💤 Спит | микрофон в фоне, команды не принимаются |
| 🎤 Слушаю | идёт запись, ждём конца фразы |
| 🧠 Думаю | распознали, разбираем намерение |
| 🔊 Говорю | озвучиваем ответ |
| ⛔ Прервано | вы заговорили — ассистент замолчал |

## Что означает push-to-talk

Пока держишь кнопку — ассистент слушает. Отпустил — окно закрылось
**немедленно**, без ожидания таймаута.

Пока кнопка зажата, обычная активация (mouse5, `Ctrl+Space`) не
срабатывает: иначе случайный клик во время фразы запустил бы команду
посреди сказанного.

## Срабатывание по переходу

Активация срабатывает в момент **нажатия**, а не пока кнопка зажата.
Удержание кнопки не переоткрывает окно каждые 0.35 секунды — как только
сочетание нажато, дальше тишина до отпускания.

Клавиши и мышь проверяются независимо: если держишь `mouse5` и нажмёшь
`Ctrl+Space`, сработает именно `Ctrl+Space`.

## Проблема, о которой стоит знать

Если перехват не запустился вовсе, ассистент об этом скажет при старте:

```
Активация не работает: мышь недоступна (...)
Пока голос недоступен — пишите команды в консоль.
```

Это не поломка: голосовой ввод требует живого рабочего стола с
клавиатурой и мышью. В консоли при этом всё работает.

## Архитектура

Клавиатура и мышь — разные API: `RegisterHotKey` из Win32 умеет только
клавиши, а боковые кнопки приходят отдельными сообщениями окна и требуют
low-level hook. Реализация — `sinaps/ui/trigger.py`.
